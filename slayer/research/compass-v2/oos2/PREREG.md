## 4. Rules (binding)
1. **One look.** LOCKED-2 is scored ONCE, by a blind scorer who receives only this file, `LOCKED2.json`, the frozen
   spec (c45a7d2) and the cache path — not the research notes. Both executions, as in the first look:
   (a) spec-literal: the frozen rule `candidates.k5_overnight_spx_hard` through `chal.Sessions(days, roots=['SPXW'],
   session='overnight')`, hard exit on the one-minute path (hit50 / worstPre / flatBid), fee $0.65/contract/side
   (`blind/k5_locked.py` logic); (b) protocol item 2: the same calls re-settled by the foundation simulator on 1-s NBBO
   (ask in, bid out, +2 s latency, displayed size, 09:20 flat; `blind/k5_locked_exec.py` logic).
2. **Reported numbers:** n, win rate, expectancy/trade with and without fee, each with a 95% session-clustered
   bootstrap CI; per tier (A/B), per period, per regime label above; pooled with the first look (n = 59) for the
   protocol item 7 gate (≥ 150 trades, CI excludes 0, win ≥ 55% or payoff-adjusted, PBO/DSR as already computed for
   the family). A regime "works" when its LOCKED-2 fee-inclusive protocol-execution expectancy is > 0 with ≥ 20 calls
   (declared now).
3. **Missing sessions** (terminal gap, build failure) are reported as missing with their count; nothing is fetched
   or rebuilt after any result is seen. Sessions not yet built when the scorer runs are NOT scored later as a
   second look: the scorer scores the sessions built at that moment and the rest are forfeited unless the owner
   registers a LOCKED-3 before they are built.
4. **No tuning, no peeking:** worker OOS2 builds rows only (fetch → engine replay → rows), never runs K5 or any
   candidate on them, never reads outcome columns (hit50, worstPre, flatBid, pnl*, exit*, best, fill), and never
   changes the spec. The build logs print only marks/rows/would-call counts.
5. **Build provenance:** the challenger's own pipeline, verbatim copies in `pipeline/` (fetch.ts, build.ts,
   localHost.ts; only the import paths point at the challenger engine tree, DATA at `v2data/oos2`, and a
   `CHAL_DAYS` allow-list so no session outside this block is fetched). Engine tree: worktree
   agent-a3673bb87994bc8be @ 8ae094a; `ENGINE_MANIFEST.sha256` hashes its 748 files. Parity check before any
   LOCKED-2 day: 2022-03-15 (an already-used DEV day) rebuilt from a copy of its raw cache gave 7179 rows identical in
   all 109 kept columns and the same 4 engine would-calls as the challenger's own file.
6. **Fetch scope:** `--roots SPXW` (the SPXW 0DTE and weekly chains over the overnight, pre, regular and curb
   sessions, open interest, Book C's 15:20:15 board, SPX + SPY/QQQ/IWM/SMH/XLF/XLE/GDX/BITO 1-minute bars) — the
   same subset the 2022 regime samples K5 learned on were built from (SPY, QQQ, IWM, SPXW). K5 reads SPXW rows only
   and the seat rule gives one call a night to one root, so other roots' rows cannot change its calls.
7. **Priority** if the build does not finish: 2025 Q2–Q4, then 2023, then 2022 Nov–Dec + Jan–Feb, then 2026 H1,
   then 2024, then 2026-11. The scorer reports which periods were complete.
